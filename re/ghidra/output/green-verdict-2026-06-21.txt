Q4. THE VERDICT
--------------------------------------------------------------------------------
CAN the mod ref-free green a TARGET planet's flora/fauna for FRESH instances?

NO — not by the ID_52161 + ID_52158 pair as written, for any species whose base
form returns {0,0,0} from vtable[0xa8] (the normal FLOR / NPC_ case). The green
tree is keyed by a 3-component CATALOG key that, for these forms, is MINTED

resolves to a DIFFERENT key and never matches -> renders BLUE. This is a hard
engine design fact (ID_137052 is unconditionally timestamp-based), not a bug in
the mod's offsets.

The persistent, per-type state that DOES survive reload and IS honored is the

the OUTLINE tree-reader (ID_52162) keys on the catalog key, not that flag, so the
flag alone does not produce the green outline for fresh instances. (It does make
GetSurveyPercent / the data 100% correct, which already works ref-free.)

The ground-truth fact (a genuinely 100%-surveyed planet greens fresh instances on
reload) is NOT a counterexample: in that case the engine, during the REAL in-world
scan, wrote tree nodes whose keys came from the species' actual resource-id path
for THAT planet's authored instances — OR the renderer's green for a fully
surveyed planet is gated by the per-(planet,species) scanned-flag through a code
path (ID_52159, keyed by species formID) that we have NOT been able to trip
ref-free with a matching catalog key. Either way, the reproducible lever we can
